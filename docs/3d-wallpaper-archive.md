## 0. 结论摘要

**技术方案（两条路线，同一条重建链）**：

```
① 照片路线：单张照片 → 端侧单目深度估计 → 深度网格（照片层/背景补洞层/远景板）
   → 渲染 72 帧带视差的多视角帧（自报内参与位姿）→ PushFrame → 3DGS 重建 → MP4
② 预置路线：离线合成数据集（等距柱状地球纹理 + 星壳环境，按声明位姿域环绕"拍摄"）
   → 应用内逐帧解码灌入预置帧队列 → 同一条 PushFrame 全链 → 预置壁纸成品 MP4
```

**已验证的结论**：

- 【实测】Spatial Recon Kit 的 `PushFrame` 自定义帧路径可用：自合成帧 + 自报位姿可重建
  成功（重建四阶段全部完成，约 87 秒出片，无降级 fallback）。
- 【实测】三个几何前提是硬性的：图像与位姿必须自洽、场景必须非共面、相邻关键帧位移
  必须落在可匹配窗口内（F1/F5）。
- 【实测】纯水平轨道存在"纵向尺度与 fy 精确不可观测"的数学退化，会导致重建比例随机
  失真；修复手段为对角弧轨道（F6）。预置路线的数据集把该结论直接烧进了生成器。
- 【实测】重建解的内参与**观测内容**耦合：refined 纵横比（fy/fx）随素材漂移、同素材多轮
  稳定，且直接等于重建模型的纵横比读数（F15）。
- 【实测】模型上可见的"黑斑贴边"可在模型里定位：球缘一圈**暗高斯点**（而非缺几何）——
  由 PLY 侧车离线解剖与端侧几何自检共同确认（F16）。
- 【实测】导出/展示环节（运镜、朝向、视场）同样是内容相关的黑盒产物，不能写死补偿（F17）。
- 【实测】离线高质量深度（扩散模型）可显著改善输入质量（§5.1）。

## 1. 问题与背景

**目标**：单张照片 → 生成"3D 影像" → 保存图库 → 可被系统设为壁纸。

**平台约束（决定了方案形态）**：

- 【官方】Spatial Recon Kit（空间建模套件）集成 3DGS 模型的渲染与运算能力；重建
  （C/C++）支持"多视角图像 + 相机内参 + 位姿"输入，输出 3DGS 模型（MP4/PLY）。
- 【SDK】SDK 中该 Kit 的 C 接口共 15 个函数（重建/会话/保存），ArkTS 侧提供模型加载
  （MP4/PLY/GLB）与编辑能力；**两种形态均无"单图直接输入"的入口**。
- 【官方】文档更新记录（2026-07-28）中有"Spatial Recon Kit删除文档，因空间照片功能的
  技术策略调整，该功能暂时下线"的记载；被删除文档的具体内容不在公开渠道，**本文不对
  其功能范围作推断**。
- ⇒ 结论：若要在单图与 3D 影像之间建立通路，需自行构造"多视角帧"作为该 Kit 的输入，
  即本方案。

**该 Kit 的输入硬约束（官方原文）**：

| 约束 | 内容 |
|---|---|
| 输入尺寸 | 仅 1080×1440（其余尺寸"结果未定义"） |
| 输入格式 | 仅 RGB 三通道紧凑布局（3 字节/像素） |
| 每帧数据 | 图像 + 内参（focalX/focalY/principalX/principalY/8 畸变系数）+ 位姿（position[3] + rotation[4]，四元数 [x,y,z,w]）+ 时间戳(ns) |
| 关键帧 | 由 Kit 自动挑选（应用不可控） |
| 工作目录 | 必须已存在、且为应用文件目录子目录 |
| 会话 | 同一时刻仅允许一个重建/保存会话；任务在途销毁属未定义行为 |
| 设备 | 仅 Kirin 9020/9030 系列及以后保证体验；仅中国境内（港澳台除外） |
| 输出 | MP4 容器内含 3DGS 模型数据（HEVC 视频轨 + GLTF 模型数据 + PNG 封面轨），容器规范未公开 |

## 2. 已验证的链路与真机证据

```
相册选图
  → 解码 + 居中裁 3:4（长边 ≤1440，例：809×1079）
  → 端侧单目深度估计（Depth Anything V2 Small + MindSpore Lite，546×728 相对逆深度，约 2.5s）
  → 三层深度网格场景（纯 2D 构建，与相机无关）:
       ① 照片网格（前景层）：逐像素反投影成三维网格；跨深度台阶细分 1px 平片；80px 裙边
       ② 背景层：近区 push-pull 补洞（承接主体滑开后露出的消隐带）
       ③ 远景板：模糊压暗兜底平面
  → 72 帧多视角合成（对角弧 ±5°；参考位姿帧逐像素等于原照片）
  → 逐帧 PushFrame（自报位姿）
  → 端侧 3DGS 重建（约 87s）→ 自动保存 MP4（系统识别的 3D 影像）
  → 保存图库
```

**真机出片结论**【实测】：端到端跑通——端侧深度推理 → 72 帧多视角合成（无空帧）→
Kit 重建四阶段（INIT → BUILDING → FINISHED → SAVING）全部完成，产出系统可识别的
3D 影像 MP4（非降级产物）；几何核验通过（参考位姿帧与原照片恒等、端点帧存在视差）。

### 预置路线（2026-10-10 增补）

```
离线（PC）：earth_scene.py 合成数据集
  → 等距柱状地球纹理 + 星壳环境（真 3D，随环绕产生视差）
  → 按声明的位姿域环绕"拍摄" 120 帧（1080×1440、JPEG q95、4:4:4、SSAA 2×）
  → manifest.json（帧清单 + 环绕半径 + 焦距 + 位姿域 + 背景参数，全部可追溯）
应用内：generatePresetEarth
  → 按目标帧数对数据集等距抽样（帧数 = 时长/成本的直接旋钮）
  → 逐帧解码 RGBA 1080×1440 → 预置帧队列（容量 3、背压退让，不冻结 UI 线程）
  → bridge 按 manifest 的位姿域给出环形基位姿（三域互斥有防呆）→ PushFrame 全链
  → 3DGS 重建 → MP4（预置"地球"壁纸成品）
```

**真机出片结论**【实测】：
- 数据集合成 → 端侧重建 → 保存图库 → 设为 3D 壁纸全链可用；**预置成品（地球）已作为
  内置推荐壁纸随应用分发**（用户实机验收：构图与观感已达标，同时记录了两条残留缺陷的
  量化与定因，见 F15/F16）。
- 帧数是主要成本旋钮：120 帧全量喂入时构建约 2 小时（进度约 3%/分钟）且伴随 GPU
  device-lost 复位；预置路线按抽样档位运行（现役 72 帧档），小档起步逐档上试。
- 数据集帧与位姿声明"同源同参数"是硬要求（见 F17）；判据脚本对 manifest 与**每一帧**
  的 JPEG 尺寸做机器核对，并对"位姿域 × 读取端 × native 公式域"三处配对做源码守卫。

## 4. 关键技术发现（F1~F17）

> 每条均为真机或判据级证据支撑，供避坑参考。

### F1 图像—位姿自洽 与 场景非共面 是两个独立硬前提 ⭐⭐⭐
**现象**：流程机械全通（帧全部推入、关键帧被选中），重建固定 3.4 秒失败
`[STAGE02] no 3D points`。
**根因**：① 合成器将"图像行向下"接到了"相机 Y 轴向上"——图像被垂直镜像，而
**镜像不是旋转，任何位姿约定都无法补偿**；② 首版"立体"场景正面填满画面，与纯平面
几何等价——两视图 SfM 的经典退化。
**解法**：像素 (u,v) 的射线恒为 `dir = a·X + b·Y − Z`（`b = −(v+0.5−cy)/fy`，第三项取负），
投影使用同一组公式（放在同一处维护）；场景保证至少两个深度层且在画面可见。
**配套**：判据脚本对同一批三维点核对"渲染落点 == 标准投影落点"。

### F2 失败签名相同不代表根因相同 ⭐⭐
`no 3D points` 先后由四种不同原因产生：镜像（F1①）、场景共面（F1②）、射线方向错误（F3）、
工作目录 resume 模式（F4）。**排除法应按"输入是否自洽"逐项证明，而非穷举位姿约定组合**。

### F3 几何重构与几何修复不应同时进行 ⭐⭐
将相机系改为列存储 `[right|up|-fwd]` 时，射线从 `a·right+b·up+fwd` 直译为
`basis[0]*a + basis[3]*b + basis[6]`——第 2 列是 `-fwd`，符号错误导致相机朝向背后，
72 帧全部为空图。定位依赖"实装产物级自检"：每帧降采样为 48×32 ASCII 缩略图进日志
（设备沙箱不可读时，日志缩略图是唯一的产物级取证通道）。
**教训**：重构时应同步建立产物级自检，且判据脚本应包含源码级守卫（见 F14）。

### F4 工作目录持久化会导致静默拒收关键帧 ⭐⭐⭐
该 Kit 会以工作目录内的历史数据判定为"上次训练现场"，进入 resume 模式；该模式下
`PushFrame` 仍返回 SUCCESS，但被选中的关键帧被直接丢弃（Kit 日志：
`WorkPath exists with historical data, setting mode to resume training` /
`Resume training mode, can not push frame`）。统计口径：`selected` 行数逐轮等于
`can not push frame` 行数。
**解法**：每次生成使用新建的空目录（先创建再传入，Kit 要求目录已存在），结束后回收；
产物文件放该目录之外。

### F5 位移量级守卫是本路线唯一的"成败参数" ⭐⭐⭐
Kit 自动挑选关键帧（实测 72 帧选 5~6 个），位移必须按"最坏相邻关键帧"设计：
相邻关键帧总位移应落在 **30~80 px**（精确针孔投影口径）：
- 下界 30px：低于此值三角化点不足（实测 fx=700 时 Θ=2°≈12px 失败、3°≈18px 模型破碎、
  5°≈31px 可建）；
- 上界 80px：超出特征匹配窗口（历史成功 ≈70px / 失败 ≈100px）。
且近远层滑移 ≥20px。实装含自适应钳制：位移带外自动调整轨道角并记录日志；"守护深度"
取深度分布的 p90 分位（对"近层面积小"的素材保守评估）。

### F6 比例失真的根因：纯水平轨道的精确退化 ⭐⭐⭐
**现象**：同上报 fx=fy 的多轮重建，"成功"但空间比例随机失真（重建精修内参的
fy/fx = 0.155 / 2.471 / 2.688，分别表现为宽度压缩 / 拉伸 / 不可用）。
**根因（数学严格）**：纯水平 look-at 轨道（相机中心全在 y=0、姿态只含 yaw）下
`v_i = cy − fy·Y/depth_i(X,Z,θ_i)`——Y 只出现在分子。对任意 α，变换 (Y→αY, fy→fy/α)
后所有帧所有像素不变（投影级数值复现 0.00px）⇒ "场景纵向尺度"与 fy 精确不可观测，
重建的 BA 在该零梯度方向随机漂移。
**解法**：对角弧——相机中心离开 y=0 平面、姿态含俯仰（yaw+pitch 同步扫 ±Θ），同变换下
像素变化 ≈398px（可观测）。验收读数：重建精修内参的 fy/fx（aspect）应 ≈1。
**一般教训**：向 SfM/BA 输入合成数据前先检查可观测量；"相机共面 + 无俯仰/滚转"这类
对称性会造成某方向精确不可观测，外在表现为"换参数结果随机变"。

### F7 输出颜色表现（成因未定论）
**说明**：开发期围绕成片颜色表现做过若干次 A/B 试验，并据此推断过"通道位序/匹配组件
敏感性"一类的成因。这些推断**目前无定论**，缺乏可复现证据，故不再作为结论陈述。
**结论**：本条**不作结论**。颜色表现的成因（是否位于该 Kit 内部，还是与素材分布、本项目
侧的处理有关）留待后续验证。
**工程处理**：应用侧保留了"推帧通道顺序（R/B）"开关与失败重试，作为兼容性兜底；其默认值
与重试策略属于工程折中，不代表对成因的判定。

### F8 参考位姿恒等是照片保真的硬约束 ⭐⭐
要求 θ=0 帧逐像素等于原照片的 3:4 裁剪缩放（判据断言：台阶带外恒等率 ≥99.9%，
实测 99.95%+）。两条配套结论：
- 深度场分辨率（如 546×728）**不是**画布分辨率（1080×1440）：网格角点与 UV 必须乘
  `outW/dw`、`outH/dh` 映射到画布空间，否则照片缩在画幅一角；
- 任何"分层/替换阈值"需先自问"参考视图是否仍等于原片"（阈值取低会在轮廓留下
  每帧静止的光晕）。

### F9 世界点必须构建期一次性固化 ⭐⭐⭐
**现象**：离线判据全绿，真机秒级 `no 3D points`，合成帧"有内容"。
**根因**：实装将"像素反投影为世界点"放入了逐帧循环并使用当前帧位姿——代数上该顶点
每帧都被投影回自身像素坐标（u ≡ q.x，与位姿无关）→ 72 帧画面逐帧相同（零视差），
仅上报位姿在变化 → 特征匹配无基线。
**解法**：世界点在网格构建期用参考位姿一次性反投影，逐帧仅做投影；并把"渲染函数体内
不得出现位姿基向量"写入判据的源码级守卫。
**一句话**：判据中"构建期一次性的量"，实装中一旦进入循环就会退化为恒等式。

### F10 可匹配特征应"贴近照片" ⭐⭐
单图重建中若可匹配内容只有照片本身（近景平面 + 遥远背景），照片内容将直接决定成败
（自相似/周期性照片可使三角化降至 0 点）。解法：照片按宽高比 contain 到画面内，余量
用与照片同深度的、不可重复的程序纹理补边——恒有一圈"处处唯一、非重复"的特征。
"隧道式"盒中空间（四壁贴纹理）不稳定；近景特征应贴照片，而非只放在画幅边缘。

### F11 深度网格不跨台阶连接 ⭐
深度跳变处若将四角连成同一面片，新视角下会被拉成长条纹。解法：四角 z 比 >1.15 的格子
细分到 1px 正面平行小片（四点同深）；判据断言粗格四角 z 比 ≤1.2。

### F12 重建服务对输入分布的敏感性 ⭐⭐
同配置下成败会随素材内容与色彩分布变化；且"重建成功"不等于"模型可用"——存在"重建成功
但模型混乱"的档位（比失败更不利，因成功态会阻断重试）。
**推论**：任何改变输入分布的处理（颜色、强增强）需在真实素材上验证；产物自检应覆盖
**颜色域**，而非只看亮度域。

### F13 端侧 .ms 模型部署：动态 shape ⭐⭐
本项目的深度模型（DPT 头部含 `Reshape→Conv`）静态化转换不可行（converter 报
`Unexpected input format 0`）→ 分发动态 `.ms`、端侧 `OH_AI_ModelResize` 到固定尺寸后推理。
**任何 `.ms` 接入前，应在目标 runtime 上以最小探针跑通 Build + Resize + Predict**。

### F14 判据未覆盖的路径需要源码级守卫 ⭐⭐
离线判据输入的坐标系/分辨率组合与实际链路可能不同（判据输入为画布分辨率，实装链路为
"深度场→画布"两步），导致"只在真实链路上暴露"的口径错误在判据中不可见。**数值判据
只能覆盖其运行过的输入**；未覆盖的分辨率/坐标系组合应以**源码级守卫**兜底（常量一致性、
关键函数存在性、禁用符号、调用参数形态）。

### F15 重建内参与观测内容耦合：refined 纵横比 ∝ 模型纵横比 ⭐⭐⭐
**现象**（预置路线）：数据集的帧里球是**正圆**（离线测量 1.0000），但成片/壁纸上球是
横向拉宽的（同一段成片 298 帧稳定在 **1.122**）。
**读数**：Kit 的 `GetRefinedFrame(session, …)` 给出重建精修后的内参——同一素材多轮
**逐位相同**（fx=468.14 / fy=526.35 ⇒ fy/fx=1.124），跨素材则可差 0.3~3.5 量级。
**结论**：这是"重建解的内参本身漂移"，且**精修纵横比直接等于模型纵横比**（成片按各向同性
相机渲染，实测成片 1.122 ≈ 模型 1.124）。帧是诚实的，焦距声明是诚实的，漂移发生在
对侧——**用"帧侧预拉伸"或"声明各向异性偏置"去抵消都要先假设漂移量可预测，而它随内容变**；
实测把声明按 1/B 反向偏置（ρ=0.89）直接使重建崩坏（什么都看不到），该做法已废止。
**工程态度**：把 refined fy/fx 当**读数**用（每轮日志对账），不要当修复目标；修复路径
（若有）应避开"谎报内参"（见 §6.1）。

### F16 模型临边暗点：黑斑的成因可以在模型里定位 ⭐⭐⭐
**现象**（预置路线）：球缘一圈出现"半明半暗"的贴边黑斑（盘内近黑像素 0.1~0.15%，
集中在临边方向）；同类"黑背景穿到球前"的观感在早期轮次也出现过。
**方法**：
- 端侧：`SaveResultToFile` 追加保存 **PLY 侧车**（模型侧唯一可解剖产物；沙箱目录主机
  `hdc file recv/ls` 不可读——实测 permission denied），把关键几何统计量打成日志
  （`build`/`shell`/`cover`/`lum`：半径直方图峰位、壳层三轴尺度、24×12 经纬格的点数与亮度）；
- 离线：PLY 解剖器（RANSAC 球拟合到球心系 + 经纬覆盖/亮度图）与离线 3DGS 渲染器复现成片。
**结论**：黑斑**不是缺几何**——球缘那一圈位置落在球面**之内**的暗高斯点（3DGS 为解释
"球缘硬边 ↔ 纯黑背景"在临边生成的点），渲染时与球面排序打平手，被生产端啃出来。远景点
（稀疏尾）"偏近"但不构成黑斑。
**教训**：观感缺陷（"黑背景突出到球前"）必须在**模型**里量，不能停在成片像素上；
"成功出片"与"模型可交付"是两件事（呼应 F12）。

### F17 导出与展示环节同样内容相关；预置数据集是"可控替代输入" ⭐⭐⭐
**现象**：同一模型、同一构建，导出物（MP4 内 GLB）的**朝向、视场、成片运镜**都随素材变化：
- 导出朝向：不同素材的导出朝向不一致 ⇒ `worldFlip180` 不能写死（预置路线改由数据集声明）；
- 视场：同一构建下实测 84.73°（≈声明值）与 50.83°（偏差 42%，成片被整体放大 1.73 倍）两档；
- 运镜：出现过"初始相机落在点云壳内部、从球壳内侧看"的轮次，而同一模型用其导出相机
  离线渲染却是干净圆球 ⇒ 坏的是**运镜轨**，不是模型。
**结论**：这些环节没有可写死的补偿；**与其对抗黑盒，不如给它可控的输入**——
预置数据集的设计原则由此确立（每条都有实测依据）：
1. 位姿域必须打破退化（diag-arc ±5°；同 F6）；
2. 背景必须有可匹配的非对称结构（星点/软斑；纯黑与"包住相机的球壳"都被证伪——后者
   相机在壳内，±5° 弧只重建出残片 ⇒ 空白帧）；
3. 参考帧与声明位姿同源（帧由声明几何精确重投影，判据核对两侧同式同值）；
4. 内容要有结构（如海洋加低频起伏——纯色大平面是零纹理区，毒化深度分析）；
5. 抽样档位而非全量喂入（120 帧全量 = 约 2 小时 + device-lost 风险）。

## 5. 已验证的改进方向

> §5.1 经离线对比实验验证；对应端侧集成代码在归档时未保留，方法与实验数据如下。

### 5.1 离线高质量深度（扩散模型）**【实测】**
- **实验**：同一张照片（809×1079），Marigold-LCM（Apache-2.0；消费级 GPU 约 2 秒/张；
  1024 分辨率 + 5 次集成约 10 秒/张）对比端侧 DA-V2 Small（546×728）。
- **量化**（判据指标"深度台阶带占比"，越低越好）：端侧 7.72% → Marigold 6.56% →
  1024+集成 5.60%。目视差距更显著：小模型输出在主体轮廓存在雾状渗色、发丝结构缺失；
  扩散模型输出发丝分缕可见、人景分离度明显更高。
- **集成性**：离线深度（float32，越大越近）与端侧管线天然兼容——合成管线的深度输入
  为参数传入，可来自端侧推理或离线文件。
- **许可注意**：DA-V2 系列仅 Small 为 Apache-2.0（可商用）；Base/Large/Giant 为
  CC-BY-NC，不应用于商业链路（含离线批处理产物）。Marigold v1-0/LCM 为 Apache-2.0。

### 5.2 相关开源项目调研（许可经模型卡核实）

| 类别 | 项目 | 许可 | 适用性 |
|---|---|---|---|
| 场景深度 | Marigold (depth-LCM v1-0) | Apache-2.0 | 离线深度增强候选 |
| 场景深度 | Depth Anything V2 Small | Apache-2.0 | 端侧在用 |
| 单图 3D 照片（经典） | 3D Photo Inpainting (CVPR 2020) | MIT（内置补全组件为 CC-BY-NC，需替换） | 架构与本管线同构，可参考 |
| 单图 3DGS | Apple SHARP 等 | 研究许可（非商用） | 仅技术参考 |
| 物体级 3D 生成 | TripoSR / TRELLIS | MIT | 对象为物体而非场景，与本需求不同轨 |

**共性判断**：以上项目解决的均为"图像 → 高质量数据（深度 / 3DGS）"环节；
"输出系统识别的 3D 影像"环节为平台专有，无开源替代。

### 5.3 预置数据集"地球"（已上线）**【实测】**

- **是什么**：离线合成数据集（`tools/depth_mesh/earth_scene.py`）→ 应用内预置帧队列 →
  同一条重建链 → "地球"3D 壁纸成品（内置推荐壁纸第一位，随应用分发）。
- **为什么这样做**：见 F17——展示环节不可控，就把输入做成可控、可追溯、可复核的。
- **可复核性**：数据集 manifest 记录全部来源参数（焦距/半径/位姿域/背景档位/纹理偏移），
  判据（`tools/earth_preset_check.js`）对 manifest 与每帧尺寸做机器核对，并对
  "位姿域 × ArkTS 读取端 × native 公式域"三处配对做源码守卫。
- **诊断工具链**（模型侧，随仓库发布）：PLY 侧车 → `earth_ply_probe.py`（球心系经纬图：
  缺几何 vs 黑点挡前）/ `earth_model_survey.py`（壳层三轴尺度）/ `earth_cloud_view.py`
  （点云三视图）/ `earth_splat_render.py`（离线 3DGS 复现成片）；成片侧 →
  `earth_out_measure.py`（盘纵横比与临边黑区，可在任意 mp4/png 上复算）；
  `earth_glb_extract.py`（从产物 MP4 取出内嵌 GLB/PLY）。
- **残留缺陷**（已量化定因，修法未闭环）：① 横向拉宽 = F15 的内参漂移；② 临边黑斑 = F16
  的暗高斯点。见 §6.1。

### 5.4 深度场质量算法 D1~D4（已实装，默认开）**【实测】**

- **D1** RGB 引导上采样（JBU）：深度边缘贴颜色边缘，网格角点密度不变；
- **D4** 保边预平滑：消细碎台阶（台阶不跨糊）；
- **D3** 自适应纵深：按深度直方图分离度在 k∈[2.2, 3.8] 取值（d0 恒 2 公式，相机数学零改动）；
- **D2** 主体对齐：主体蒙版门控的深度净化（蒙版外逐字节不变）。
- 离线判据 `tools/depth_mesh/depth_edge_check.js`（合成场景 + 源码级守卫；真实数据分析台
  需要画布分辨率参考深度，可选）。离线验证读数：边缘对齐分 0.206→0.445、渗色带宽
  5.97→4.89px、MAE 0.0034→0.0029。
- ⚠️ **本档改变喂给重建服务的帧统计**，真机记录过观感风险（局部拉伸带/拉丝），
  默认档变更须同图 A/B 复核（呼应 F12：重建的输入分布敏感性）。

## 6. 未竟事项（后续开发建议）

### 6.1 优先验证项
1. **闭环验证**：完整走通"出片 → 保存图库 → 系统 3D 影像 → 设为壁纸"。
2. **回归留档**：每次真机测试保留完整日志（判读行见工具脚本输出）。
3. **预置路线两条残留缺陷的确定性修法（均未闭环）**：
   - 横向拉宽（F15）：唯一"不动声明"的候选是**帧侧预拉伸**（帧按 ratio 各向异性渲染、
   声明保持诚实各向同性）——**未试**，且与已崩坏的"声明偏置"是同一物理不一致的两侧镜像，
   风险同源，建议半量版本（ratio≈1.06）先做；
   - 临边黑斑（F16）：候选是让球缘的明暗过渡更连续（把"硬边↔纯黑"的台阶变缓），
   理论依据是 3DGS 对"解释不了的黑边"会在临边生暗点——**未验证**；改动须单变量。

### 6.2 质量提升（按已验证程度排序）
- [x] 离线高质量深度（§5.1）；
- [x] 深度边缘保持上采样（RGB 引导的联合双边/引导滤波）——D1/D4，已实装默认开（§5.4）；
- [x] 自适应纵深参数（由深度直方图分位结构决定远近比）——D3（§5.4）；
- [ ] 解码尺寸提升（长边 1440 → ≥1920，消除贴图二次上采样）；
- [ ] 端侧深度 TTA（多尺度/翻转平均，成本换质量的折中项）。

### 6.3 摆脱黑盒的研究方向
- **容器格式**：检索 OpenHarmony 开源实现中的 `SpatialGltfModelPacker`；或获取
  `model_*.mp4` 样本解析盒结构；
- **把重建服务当格式转换器**：以高质量输入帧（§5.1）喂入，最小化其不确定性；
- **AR Engine 实拍路径**（`PushARFrame`）：该 Kit 的原生输入形态（位姿来自 AR 会话），
  用于实物/环境扫描比自合成帧更稳定；
- **已评估并否决**：以视频生成模型生成"环绕视频"再喂重建服务——生成视频的多视角
  几何一致性无保证（像素与位姿无法自洽），与几何重建引擎的本质冲突。

## 结语

本档案记录了一条可复现的路径：以自建的"深度 → 网格 → 多视角帧"管线（照片路线）与
"离线合成数据集"管线（预置路线），使 3DGS 重建服务能够接受普通照片或合成数据作为输入，
产出平台生态内的 3D 影像。参数、判据与避坑结论均在上文；未竟事项列于 §6，供后续开发
继续推进。
